# 2026-08-17

## pi reviewer hardened against dev-flavoured pi config

The pi adapter now passes `--no-extensions --no-skills --no-prompt-templates --no-approve --offline` on every run. Motivation: the same pi install is about to serve double duty as an interactive dev harness (local inference providers, MCP servers via extensions, trusted project `.pi/` dirs), and review runs must not see any of it. The non-obvious points:

- **The sharp leak was the trust store, not the extensions.** pi remembers interactive trust decisions in `<agentDir>/trust.json` (nearest-ancestor match). Print-mode runs in an *untrusted* cwd resolve untrusted on their own — but once a repo is trusted for development, review runs in that repo would load its `.pi/` settings and *execute its project extensions*. `--no-approve` overrides trust resolution unconditionally; it's the flag doing the real isolation work.
- **`--tools` already gated extension tools** (the allowlist spans built-in, extension, and custom tools), but extension *code* still executed at session start — an MCP-adapter extension would spawn its servers inside every review. `--no-extensions` is what stops the loading, not the tool gate.
- **`--offline` does not touch auth.** Verified in pi 0.80.7 source: `PI_OFFLINE` gates the version check, managed binary downloads (fd/rg), model catalog refresh, and package operations only. No reference in the auth path; oauth token refresh and the model API call are unaffected. Verified live with `openai-codex/gpt-5.6-sol`.
- **Flag set and event shape verified against pi 0.80.7** (comments updated from 0.78.0; `message_end` shape unchanged). A pi version bump is the re-check trigger, per the comments in `pi.go`/`jsonl.go`.
- **Coupled copy: mercurius.** `mercurius/internal/reviewer/pi` is the original this adapter was lifted from and got the identical change (flags, comments, test assertion) in the same session. The two copies must move together until mercurius consumes this package.
- **Test gap:** this repo's `reviewer/pi` has no tests; the arg vector is only asserted by mercurius's fake-pi test. A port of that fake-pi harness here would close it.
- **Live state:** terminus consumes theharnessbody v0.1.0, so the bake-in reaches terminus only at the next tag + go.mod bump. Until then Michael's `~/.config/terminus/config.yaml` carries the same five flags via `extra_args` (marked to be removed once the adapter change lands in a release).
